# MapTalk 朋友故事线设计与验收

2026 年 10 月 26 日。状态：本地实现与回归验收，未部署后端、未安装手机。

改动前的回退版本为 [`97cfb07`](https://github.com/maptalk27-cloud/maptalk/commit/97cfb07d67d85a5d4fbf4d9582051ac65ed91e94)，已推送到 `origin/main`。用户随后授权按设计直接实现。开发不改变已安装的 App，也不改变云资源、配额和费用方案；地点历史接口的线上部署另行确认。

## 产品决定

MapTalk 同时服务两件不同的事：看看朋友最近经历了什么，以及看看一个地方有什么值得发现。前者按人连续浏览，后者按地点积累内容。

建议把首页顶部改为每位发布者一个故事入口。点进去直接看他的分享，不需要先选地点、再选这个人。地图中的 POI 继续作为共同的地点，承载地点名称、坐标、分类、可用地址信息、不同人的打卡和地点讨论。同一条分享从人物和地点两个入口访问，不复制内容。

这一版不是新增一个需要用户创建的 Story 或 Folder。用户继续用原有 POI、Reel 发布方式，系统自动组织近期内容。MyMap 的记录和 Collection 不变。

本轮按以下默认方案实现，真实手机手感和产品取舍由用户回来验收。

## 一次具体体验

Alice 先在机场发一段视频，接着发一条包含九张照片的 Reel，之后在咖啡店打卡。Bob 也在这家咖啡店留下过内容。

首页只出现一个 Alice 入口。点 Alice 后，地图定位机场，底部直接展示 Alice 那次打卡的视频。点右侧进入她的 Reel，保留原有九图排版和文案。点某张图，用现有大图查看器看图片；退出仍是 Alice 的这条 Reel。再点右侧进入咖啡店打卡，地图才移动到咖啡店。

此时横滑可以切换到 Bob。若 Bob 当前内容也在同一家店，内容切换，地图不重新飞行。

另一条路径是留在 Alice 的打卡，点咖啡店名称进入这个地点，先看最近 12 次有权访问的打卡，包括其他人的记录；点「Load earlier visits」逐页追加更早内容，不一次下载这家店全部历史视频。退出地点，回到 Alice 原来的内容和浏览位置，而不是停在刚刚查看的 Bob 的个人故事里。

## 不变的内容关系

| 对象 | 它是什么 | 本次是否改变 |
| --- | --- | --- |
| 用户 | 分享的作者 | 不改变身份和权限 |
| POI 地点 | 多次打卡共同关联的地方，不属于某一位作者 | 保留，仍可从地图访问 |
| 一次 POI 打卡 | 某个人在某时发布的一次记录 | 保留原记录 ID，不与别次打卡合并 |
| POI 切片 | 这次打卡中的一张照片或一个视频 | 直接用于人物故事，不再先打开地点再选人 |
| Reel | 原来的完整帖子，有文案、媒体和可选 Bubble | 保留原卡片格式和原帖子 ID |
| Bubble | Reel 主动打开的附属内容集合 | 不自动插入作者故事，不改成私有 Folder |
| Collection | MyMap 中用户自己整理的本地文件夹 | 完全不加入公开故事系统 |

一个地点可以有多位作者；一位作者可以在多个地点留下记录。人物故事是对记录的另一种组织方式，不把地点变成某个人的帖子。

## 首页与地图

### 顶部人物入口

- 每个有合格近期内容的作者最多一个入口，POI 与 Reel 不分两个头像。
- 沿用现有头像和未读环的视觉语言，不增加 Stories 标题、类型标签或文件夹外壳。
- 未读作者排在已读作者之前，同组按最近公开发布时间排序；稳定 ID 用于同时间的确定性排序。
- 当前用户有合格公开内容时可保留自己的一个入口，不新增发布按钮或空头像占位。
- 浏览开始后冻结本次作者顺序，新发布不在手势进行中把作者挪到其他位置。
- 没有近期内容就不显示空故事栏，地图和现有发布入口仍可使用。
- 地图平移、缩放、搜索结果变化不能增删这个故事栏。它不是屏幕内地点搜索结果的投影。

### 地图默认状态

本方案不再把每条 Reel 都画成一个醒目的大头像，否则顶部去重后地图仍然刷屏。

建议默认地图以地点和内容为主：POI 保留现有类别标记，Reel 使用已有的紧凑内容缩略标记。沿用现有视口、遮挡、密度和点击选择策略，不新造聚类文件夹、不自动错开真实坐标，也不强制把所有地点图标换成新设计。

大头像作为「当前正在看的那条分享」的强调，不作为朋友实时位置。进入故事后只突出当前内容的位置；其他地点维持安静的地图背景。没有必要画出某人的所有路线，也不在初始进入时缩到能装下他全部地点的世界视角。

本轮仅在首页人物故事模式采用紧凑 Reel 标记和当前作者强调；个人主页、MyMap、地点和通知不套用这项改动。

### 地点与长期内容

历史 POI 继续通过现有安静标记和动态渲染策略显示；新打卡不创建第二个相同地点标记。近期状态和历史状态是同一个地点的两种表现，不同时画两份。

Reel 过期仍按现有规则离开公开地图，不因为属于某人的故事而自动变成永久 POI。个人主页和 MyMap 的保留规则不变。

地点只展示实际存在的信息。当前数据并不保证完整邮政地址；没有地址时展示地点名和地图位置，不拼造门牌号，不把坐标标签冒充地址。

## 故事里的一页是什么

建议把「发布记录」和「当前显示的一页」区分开。这样能保持原始内容身份，同时复用 POI 已有切片。

| 内容 | 外层故事的一页 | 查看内部内容 |
| --- | --- | --- |
| 带照片或视频的 POI 打卡 | 原打卡中的一个媒体切片；兼容多媒体旧记录，按原媒体顺序展开 | 直接显示作者、媒体、时间和地点入口，不再选择一次作者 |
| 真正无媒体的 POI 打卡 | 轻量地点记录页 | 显示作者、地点和时间，不渲染空黑图或虚构照片 |
| 带媒体的 Reel | 完整原 Reel 卡片 | 九图排版、文案、视频和 Bubble 保留；点图进入原媒体查看器 |
| 纯文字 Reel | 完整原文字卡片 | 阅读和评论按原卡片处理 |
| 媒体尚未加载 | 原本那一页的占位和加载状态 | 页数及身份不变，不能误判为无媒体打卡 |

### 关于 Reel 九张照片的明确取舍

前面讨论过「点边缘先逐张看完 Reel 的照片，再到下一帖」。这与完整保留现有 Reel 九图卡片不是同一种呈现方式。

本稿默认选择保留完整原卡片：外层点右边进入下一项内容；想看照片细节，点图进入现有查看器，在其中左右滑动看本帖媒体。九张图仍然可见、可访问，但不会被强制拆成九个外层故事页。

如果后续决定所有照片都像 Ins Story 一样逐张播放，应单独设计仅用于朋友故事的 Reel 呈现方式，复用底层媒体组件和原帖子身份；不能宣称只换导航，也不能改坏地图、MyMap 和通知里的原 Reel 卡片。这个选项不在本稿默认实现范围内。

## 浏览顺序与进度

第一版沿用现有 72 小时近期窗口，先验证浏览模型，不同时实验新的过期时长。

- 每条记录独立按首次公开发布时间判断是否合格，然后按作者分组。新打卡不让同人的旧内容重新活跃。
- 同一人的发布按首次公开时间从早到晚排列；同一时刻用稳定记录 ID 排序，打卡内部按媒体原顺序排列。
- 第一次进入该作者，定位首个未读页。全部已读时从最新一条发布的第一页开始，允许向左回看。
- 同一次浏览中切回一个作者，恢复该作者上次停留的位置，不每次重新寻找第一条。
- 点第一个内容的左边不退出，也不跨到前一位朋友。点最后一个内容的右边不偷偷换人；对应的上一项／下一项按钮置灰，用户仍可横滑换朋友。
- 只有一位作者时，横滑保持当前内容，不循环、不打开空白页。
- 展示离散页进度；很多页时用可读的数字进度，不铺几十根极细线。Reel 整卡计一页，其媒体查看器有自己的媒体进度。
- 每个人可以发很多内容，但不因此占更多首页入口。第一版不添加每日发布次数限制。

首次公开时间与拍摄时间分开。昨晚离线拍摄、今天才成功公开的内容，按今天的公开时间进入故事；原拍摄时间留在记录中。上传重试、编辑文案、点赞或评论不能刷新公开时间。

## 页面与动作

### 继续使用现有两档卡片

默认点人物入口后进入地图可见的缩略阅读态，复用 compact 和 large 两档，不增加第三档。人物模式在原约 35% 的卡片空间上补上 72pt 导航空间（小屏上限 55%），确保原照片、时间、点赞和 Bubble 不被挤掉；同一次会话各页使用同一个高度。普通地图卡片和 MyMap 仍使用原高度，镜头遮挡与右侧按钮按实际人物卡片高度计算。

Reel 原卡片继续负责内容展示。POI 在人物故事中增加一个明确限定作者和打卡的切片呈现，复用现有媒体、头像、时间组件；完整公共地点卡仍使用原来的 POI 呈现。不要把人物 POI 切片伪装为新 Reel。

缩略态点非控件的中央内容区展开。已展开时切内容、切朋友都保持展开，不每次回落缩略态。关闭再进入一个新故事会话，才重新应用入口默认档位。

### 手势规则

| 手势起点与动作 | 结果 |
| --- | --- |
| 故事内容舞台左右边缘轻点 | 同一个人的前一页或后一页 |
| 故事卡片内明显横向滑动 | 前一位或后一位朋友 |
| 露出的地图内拖动或缩放 | 只操作地图，不切朋友 |
| 缩略卡片中央非控件区轻点 | 展开同一内容 |
| 展开态纵向滚动 | 阅读卡片内容和评论；滚到顶部后才交还下拉手势 |
| 展开态下拉 | 收回当前故事的缩略态；人和内容不变 |
| 缩略态下拉 | 退出故事，恢复进入前的地图状态 |
| 明确的关闭按钮 | 一次退出整个朋友故事，不要求连续下拉两次 |
| Reel 图片在展开态被点击 | 打开原媒体查看器；外层故事暂停 |
| 媒体查看器内横滑 | 只切本帖图片或视频，不切朋友 |
| Bubble 被点击 | 进入原 Bubble 内部浏览；外层故事暂停 |
| 媒体播放 | 不自动推进；进入地点、Bubble、原查看器或离开前台时暂停。首版不增加长按暂停，保留顺畅的原生下拉退出；Reel 保留原查看器操作 |

边缘点击区不能覆盖头像、地点、心形、评论、菜单、Bubble 或媒体点击目标。缩略态中央展开与边缘翻页要有明确的命中区域。

尤其在展开的 Reel 九图中，点图片必须仍然打开图片，不能因为图片在左列就误翻到上一帖。因此在故事容器的顶部人物／进度栏提供轻量的上一项、下一项入口，点击区域至少 44pt；这两个入口属于故事导航，不加进原帖卡片。POI 媒体舞台的左右轻点是快捷操作，Reel 展开时以原卡片控件优先，不在九图上铺全屏透明点击层。原型需验证这项折中；若认为上下两种点击方式不够统一，就应重新评审 Reel 的独立故事呈现，而不是牺牲原卡片可用性。

VoiceOver 提供「上一项」「下一项」「上一位」「下一位」的可访问操作，不能只依赖看不见的边缘区。

横滑先判断方向再锁定：斜向或垂直拖动不能提前抢到朋友切换。取消拖拽后保持原内容、原镜头、原已读状态。手势阈值在原型中测定，不通过给所有内部 ScrollView 禁止滚动来解决冲突。

### 第一版不自动切故事

当前视频可以正常播放并沿用已有静音／音频规则，但照片、文字、Reel 和 POI 都由用户决定何时翻页，不倒计时跳到下一项，更不自动换朋友。

原因是混合内容没有统一阅读时长：纯文字、九张图、一段视频和一个 Bubble 入口不能都按几秒钟处理。现有 POI 播放器按估算视频时长、最多 20 秒自动切页，不适合直接继承。

进后台、打开评论、编辑、地点、个人资料、媒体查看器或 Bubble 时，外层暂停。返回恢复原位置；同一时刻只能有一个实际播放并发声的视频。预加载不等于预播放。

## 地图如何跟随

| 情况 | 镜头行为 |
| --- | --- |
| 首次打开朋友 | 聚焦实际选中的第一页，不对这个人的全部地点做 fit |
| 同一 POI 的连续切片或同店不同人 | 保持当前镜头，不抖动、不重复缩放 |
| 明确切换到不同地点 | 使用现有飞行控制器和遮挡修正，聚焦新内容 |
| 拖拽尚未提交或取消 | 不提前飞行 |
| 快速连点几个不同地点 | 取消旧目标，只让最后提交的目标生效 |
| 用户手动平移地图 | 保留用户位置，直到下一次明确的内容切换；同一页刷新不拉回 |
| 地图被全屏媒体或其他页面盖住 | 不在背后演飞行；返回可见地图时同步当前内容 |
| 跨城市或跨大陆 | 使用短的目标过渡，不播放漫长的世界缩放动画 |
| 内容没有有效坐标 | 保留地图，不回西雅图、不定位手机当前位置、不制造假地点 |

POI 故事使用所关联地点的标准坐标，避免同店多次打卡的 GPS 波动让镜头不断移动；Reel 使用该帖发布位置。原始发布 GPS 不改写。两者都不是实时定位。

取景使用实际可见地图区域：扣除顶部故事栏、底部卡片和安全区域，目标落在可见区域中心。复用已有目标计算与飞行实现，不能只移动数学上的屏幕中心。窗口大小和卡片档位变化应重新计算遮挡，不重新挑选内容。

Reel 附带的 Bubble 不参与父帖初始取景；用户主动打开 Bubble 后，才按其内部多点使用原有 fit 规则。本文不另定一套缩放半径，初始沿用当前 MapTalk 参数，再在同城、机场、跨城场景中一起验收。

## 返回路径

朋友故事是一个明确的会话。进入时保存来路、原地图相机、原选中项；会话内部保存当前作者、记录、切片和卡片档位。

```text
原地图
└─ 朋友故事 Alice 的某一条内容
   ├─ 原 Reel 媒体查看器
   ├─ 公共地点详情
   │  └─ 该地点其他人的切片
   ├─ 原 Bubble
   │  └─ 子 Bubble
   ├─ 原评论界面
   └─ 个人资料
```

每个内层退出只退一层，恢复精确的父内容、媒体位置、卡片档位和用户调整后的地图相机。不得靠重新计算「这个人的最新一条」找回父页面。

关闭故事则回原地图。人物浏览中点背景地图的另一个地点，也先作为临时地点深入处理，返回仍是原故事，不偷偷改成全局 Feed 序列。若用户想纯粹探索，关闭故事后继续原地图。

通知保持当前的独立单帖回看：从通知点帖子、打开 Bubble、下拉退出，都回通知来路，不附加朋友左右切换。MyMap、个人主页和公开地点自己的浏览范围也不自动切换到朋友故事模式。

## 已读与动态变化

### 已读

- POI 按原打卡和媒体切片记录已读；无媒体打卡有单独的记录级已读键。
- 本稿把 Reel 整卡作为一页，因此沿用帖子级「看过卡片」语义，不宣称九个附件都已经逐张看完。
- 进入某人不能把该人的所有内容一次标已读，也不能把同地点其他人标已读。
- 从地点页真正看过同一 POI 切片后，人物入口同步消除那一页的未读；反向也一样。
- 媒体未就绪、只有错误占位、后台、手势预览中的下一页，不算看过。建议首个真实可见画面或可读文字稳定展示后才提交，短暂停留阈值在原型测定。
- 本地已读状态按服务器环境和登录用户隔离。第一版不承诺多设备已读同步。
- 定期清理超出近期窗口且不再被当前会话引用的已读键，不让本地存储无限积累；清理已读状态不删除原记录。
- 旧版全局已读缓存无法确认属于哪个用户时，不跨账号继承；最多出现一次重新亮环，不冒险把另一用户的阅读状态带过来。

### 新增与过期

会话建立后，作者和内容的相对顺序保持稳定。新内容先更新外部未读提示，下一次进入会话再接纳，不在观看中插页、更改当前索引。

自然过期按每条记录自己的公开时间处理，不给整个作者或地点续期。首次实现到期就移除对应页；正在看这页时，选择该作者下一条有效内容，没有则前一条，该作者没有内容则退出。计时覆盖屏幕外地点的每一次打卡，不只看某人的最新一次。进入后台后重新回来重新检查时间；永久地点历史不跟随故事过期而删除。

### 删除与权限变化

一旦客户端获知记录删除、转私密、作者被屏蔽或权限撤销，应撤掉对应页、停止播放、取消未完成加载。优先选择当前作者下一条有效内容，没有则前一条；该作者已经没有内容则退出本次故事，不随机跳到别人的帖子。

不会因为冻结会话而复活被删除的内容。不同来源返回的旧网络结果要经过现有撤回版本检查，不能再次把记录加入。

没有实时推送和网络连接时，客户端不能保证立刻知道远端撤回。恢复网络、回到前台和重新获取权限时应核对；原型和上线说明不能把「收到撤回后立即失效」说成离线也能瞬时撤回。

删除 Alice 的一次 POI 打卡只删除那次记录和关联故事页，不删除地点下 Bob 的记录。Collection 原有的地点引用和 MyMap 删除语义不随故事分组改变。

## 评论与社交动作

第一版保留已有语义，不增加第三套评论系统：

- Reel 评论仍属于原 Reel。
- POI 公共讨论仍属于地点。人物切片若提供讨论入口，要标明「地点讨论」，不能像是在私下回复当前朋友。
- 原 POI 切片播放器并没有已接好的正式点赞／个人回复功能，不能因为新壳像 Ins 就画出无效按钮。
- 给「某一次打卡」增加独立评论或私信回复，是另一项产品决定，不自动纳入这次故事重组。

如果未来新增打卡评论，应引用原打卡 ID，并与地点讨论清楚区分；旧地点评论不迁移、不重新归属当前被选中的作者。

## 现有系统的限制与上线条件

| 已确认的现状 | 对方案的影响 |
| --- | --- |
| 线上 Feed 返回当前有权访问的公开 beta 内容，并未按真实好友关系过滤 | 客户端原型可按现有作者分组，但不能把全体 beta 用户称为已建立关系的好友。若正式需求是仅好友，必须另行完成关系及服务端权限规则 |
| 后端没有现成的点赞持久化接口，真实投影里的 likes 是空数组 | 不能将 mock 中的心形操作当作上线能力；本次设计不顺带承诺完成点赞后端 |
| 本地 Reel 和 Bubble 模型存在，但服务端发布 DTO 尚无 Bubble 关系 | 保留现有渲染与返回接口，mock 可验收嵌套；跨设备发布 Bubble 需要独立补齐，不在人物分组中伪造 |
| 新的按 place ID 分页读取接口已在本地实现，线上仍是原版本 | 地点历史入口依赖后端更新；每页 12 次、用户主动加载更早记录，不显示尚未读取的总人数／总次数。未更新时显示可重试的不可用状态，不把当前 Feed 的几条记录冒充完整历史 |
| 地点数据有名称、坐标和分类，不保证详细街道地址 | 地点仍是地址信息的归属，但这一版只展示真实有的数据 |

这些限制不妨碍先验证人物故事交互，但会影响正式版能承诺什么。不能用增加客户端页面掩盖缺少服务端能力。

## 实现边界

### 本次可复用

- `ExperienceDetailView` 及原 Reel 缩略／展开卡片、媒体网格、媒体查看器。
- POI 的媒体显示、头像、时间和地点信息组件；新人物场景只接收所选打卡，不传入整家店全部人的内容。
- 原 Bubble scope、面包屑和多点取景。
- 地图飞行控制器、可视区域遮挡修正和地图标记密度策略。
- 现有音频会话、视频独占播放、下拉滚动交接和 pager 纵向回弹修复。
- 原始发布、上传重试、删除及私密内容隔离，不为故事另发一份记录。

### 必须分开的状态

`当前作者`、`当前原始发布`、`当前媒体切片`、`当前地图目标`不能都塞进一个 UUID。作者入口的 ID 是用户，地点 ID 是地点，原帖 ID 是发布，媒体 ID 是资产，职责不同。

建议只新增必要的纯数据投影与会话，不做全 App 导航框架重构：

```text
PersonStoryGroup
  authorID
  entries

StoryEntry
  memoryID
  authorID
  source = reel 或 checkIn(placeID, checkInID)
  publishedAt / capturedAt / expiresAt
  pages
  locationContext
  discussionTarget

StoryPage
  stableID = memoryID + 可选 mediaID + pageKind
  kind = poiMedia 或 poiLocationOnly 或 reelCard
  metadata
  readiness

FriendStorySession
  origin
  frozenAuthorOrder
  frozenEntriesByAuthor
  authorID / entryID / pageID
  resumePositionByAuthor
  presentationDetent
  returnStack
  pauseReasons
```

这是职责示意。实现使用 `FriendStoryPage`、`FriendStoryGroup`、`FriendStorySession` 和 `FriendStoryNavigation`；页面引用原记录，绝不把每个 POI 切片转换成假 `RealPost`。

### 加载与缓存

页面身份和顺序从 `BackendMemory` 元数据建立，先有页，再逐步加载媒体。不能只从当前 `RealPost.attachments` 或 `RatedPOI.checkIns.media` 反推页数：现有投影会暂时省略尚未缓存的媒体，导致图片下载后页数突然变化。

Reel 原卡片也需要可稳定占位的附件描述，不能第一页只有两张图、其余七张下载后才被当成新发布。可以复用原布局与渲染组件，但需要补上加载状态，不是复制一套卡片。

第一版只播放当前可见内容，不预启动所有朋友的视频；父故事进入内层页面后暂停。当前 Feed 的媒体准备仍沿用已有批量缓存，并非已经完成按当前故事页的精确预取。按页优先和相邻页小量预取是后续性能优化，不增加媒体配额、单视频大小或云资源。

现有 Feed API 已有分页，客户端会读取所有分页后形成快照。小规模 beta 原型可先沿用；不能为了快只取前 100 条再分组，否则高频作者仍可能挤掉其他所有作者。增长后才考虑作者摘要和按作者分页接口，并用实际数据量决定，不在这轮先造推荐服务。

### 连续切换不重建卡片

朋友模式里，当前卡片渲染器只渲染当前一项。原全局横向 pager 不能同时挂在外层朋友横滑之下。

当前 `MapExperiencePresentation.presentNewContent()` 会在部分展开态切换中关闭并重新打开 native sheet。这适合原有某些入口重置，不适合连续故事切换。新故事会话初次进入时可使用原呈现机制，内部翻页只更新稳定 cursor 和内容；保留档位，不调用全局重置、不重新生成整个 sheet 的 identity。

MyMap 和通知保留原有呈现策略，不能为解决朋友故事的连续性全局改变它们的展开／收起语义。

## 分阶段改法

### 第一阶段 纯数据与交互原型

本地新版首页启用人物投影和会话，使用原有混合测试数据。Debug 启动参数 `--legacy-stories` 保留旧 MapTalk 路径作为对照，不替换 MyMap、通知或公共地点页面。

先验证一人一入口、精确 POI 切片、原 Reel 卡片、点前后、滑朋友、地图联动和返回。先不加真实好友关系、独立打卡评论、点赞后端、自动播放或新动画系统。

通过条件是体验和状态一致，不是头像能合并就算完成。这个阶段没有数据库迁移，也不部署。

### 第二阶段 接现有 beta 数据

接入原始 Feed 元数据、逐步媒体加载、账户隔离已读、离线缓存、删除／私密／屏蔽失效，以及实际公开时间。继续使用当前已授权的公开 beta 可见范围，UI 不声称它已经是好友专属。

本地已添加只读的按地点分页查询 `GET /v1/places/:id/memories`，复用现有公开性、双向屏蔽和 beta 可见性规则；直接按 `place_id` 查询，不依赖用户当前屏幕范围或机场的中心点。接口使用现有表，无数据库迁移或新云服务，线上部署仍需单独批准。

地点历史每次请求最多 12 次打卡，仅准备这一页的媒体，保留已有的四请求并发上限。更早内容由「Load earlier visits」明确触发；不在后台遍历全部游标，也不把已加载的页数当作历史总数。单页仍可能包含多个大视频，这是有界的首版方案，并非逐视频按需下载。

每页地点元数据验证成功后，单个媒体下载失败不隐藏地点和讨论。加载更早页遇到网络错误时，已验证的内容仍可浏览，并提供原游标重试；权限、登录、撤回版本变化则清空旧快照。请求失效但页面还在时提供重试，不无限 loading。最终线上地点入口以接口部署、分页追加／失败重试及权限失效测试通过为验收条件。

### 第三阶段 确认产品范围并上线

决定是否要求真正好友专属。若要求，先完成好友关系与服务端访问规则，测试已有可见内容不会越权；该数据库／后端变更单独确认和部署。若仍是亲友小范围公开 beta，则以当前可见发布者的故事推出，不假称已具备好友权限。

点赞持久化、公开 Bubble 跨设备存储、打卡独立回复分别列为现有能力缺口，不夹带在导航重构中。

改动前的回退版本独立保存，旧入口在验证期间保留开发开关。前端先完成模拟器回归，再按用户要求覆盖安装，保留原数据和待上传内容；真实手机体验由用户验收。不自动升级后端、安装手机或切换线上开关。

后端若需要更新，继续执行项目要求的测试、加密备份和恢复验证，取得对应部署许可。不能把本次设计与本地实现授权当作部署授权。

## 验收清单

### 内容和入口

- A 同店五次、异地两次、两条 Reel：首页一个 A；原记录一条不丢、不重复。
- A 与 B 同店：点 A 只看到 A 的分享，点地点可以看到两人的可见记录，人数为两人而非打卡次数。
- 过期打卡与新打卡同属 A：新打卡不复活旧切片。
- 一次 POI 无媒体与一次 POI 媒体尚在加载：两者显示和已读处理不同。
- Reel 纯文字、单视频、九媒体、没有文案：原格式正确，没有空文案占位。
- 地点资料不完整：不伪造地址、分类或人物实时位置。

### 手势和返回

- 点前后只在当前朋友内移动；滑朋友不同时翻本帖照片。
- 横滑取消、斜滑、慢速纵拉、评论滚动不会误换朋友。
- 从地图开始拖动只移动地图；从卡片开始操作有确定的方向归属。
- 九图 Reel 点第六张、媒体内横滑、关闭：仍是原 Reel 和原朋友。
- A 的切片进入地点、再看 B 的切片、逐层退出：准确回 A，不落入全局 Feed。
- Reel 进入 Bubble 再进入子 Bubble：返回保留父帖、页位置、展开档位和地图。
- 展开态换内容／换人不缩回、不闪黑、不关闭重开 sheet。
- 关闭故事和下拉收起区分明确；最后一位、第一条、最后一页没有隐式跨人跳转。
- 通知打开帖子并退出仍回通知；MyMap、个人主页、原地点浏览没有新手势污染。

### 地图和媒体

- 同地点连续切片和换人不重新飞行；不同地点只在切换提交后飞行。
- 快速连点、飞行途中再切换，最终卡片和镜头一致。
- 机场大地标、同城小店、跨城、跨大陆、不合法坐标都有稳定结果。
- 卡片遮挡改变后目标仍在可见区域；不聚焦 Bubble 的全部点来代替父 Reel 的位置。
- 地图手动平移后媒体下载／状态刷新不拉回镜头。
- 弱网、断网、加载失败不标已读、不跳过页面、不改变顺序；允许用户继续导航。
- 视频超过 20 秒不会被故事计时器截断；后台、内层页面和邻页预取不产生双重声音。

### 生命周期和权限

- 内容在显示、拖拽、缓冲期间删除或收到转私密／屏蔽信息：撤掉对应页，旧回包不能复活。
- 该朋友的最后一条被删除：退出到明确来路，不打开别人的内容。
- 新内容在观看中到达：当前页和作者顺序不跳，退出再进可见新内容。
- 昨晚离线记录今天公开：使用首次公开时间排序和过期，重传不续期。
- 注销、切账号、切环境：没有上一个用户的未读、故事内容或缓存会话泄漏。
- 当前页自然过期及后台回来：不重新进入过期内容，不把永久地点历史删掉。
- 超过一页 Feed、单作者占据最新 100 条：其他可见作者仍能出现，不被首次分页截断隐藏。
- Collection 成员、私有记录、待上传队列、原发表时间和评论归属不变。

### 性能与验证方法

使用固定时钟、确定性 ID 和可控制媒体就绪状态测试投影及状态转移。至少覆盖单作者、多作者、共享地点、超过 API 单页数量和媒体渐进到达。

UI 测试复用现有模拟器，覆盖横滑、斜滑、下拉、嵌套返回和截图。使用较大元数据样本检查排序及布局，不同时加载几百段视频。观察播放器数量、可取消相机任务、预取并发和回到原地图的状态；这一轮不引入付费遥测服务。

真正的顺滑度、手指命中和长视频体验仍须在用户手机上验收，不能仅凭 UI 测试通过宣称已经达到最终手感。

## 本轮已采用的体验取舍

1. Reel 保留完整原卡片，不拆成新的逐媒体故事格式。
2. 点人物先进入地图可见的缩略态；展开后翻页和换人都保留大图状态。
3. 在当前公开 beta 可见范围验证人物故事，不把客户端分组冒充好友权限。
4. 内容由用户手动翻页；不倒计时跳页，不添加新的 Story 创建入口。

这些是本版的直接实现默认值，不增加设置项。回来验收时优先看实际浏览和返回是否自然，再决定是否调整，不以重写所有卡片为前提。
